## Problem

Nine modules under `src/bilinc/` have no caller anywhere the code runs. Re-checked on 371cdfc by grep
over `src scripts benchmarks examples tests cloud .github pyproject.toml MANIFEST.in docs/public`:

| File | References on 371cdfc |
|---|---|
| `mcp_server/server.py` | none (a `DeprecationWarning` shim) |
| `mcp_server/_deprecated_server.py` | none (shim) |
| `retrieval/__init__.py`, `retrieval/hybrid.py` | only each other; `MANIFEST.in:10` prunes the package; the forbidden-prefix lists in tests/test_cloud_only_package.py:396 and tests/test_wiki_import_boundary.py:25 (guards, not imports) |
| `core/kg_retrieval.py` | only the lazy map `core/__init__.py:46-48` |
| `core/dual_process.py` | `core/stateplane.py:31` (import), `:287-289` (objects built in every `StatePlane.__init__`), `:3654-3658` (`route_query`, which nothing calls), `:3675` (`"arbiter"` key in `stats()`); lazy map `core/__init__.py:30-32` |
| `core/confidence.py` | `core/stateplane.py:30, 286`; `core/dual_process.py`; lazy map `core/__init__.py:28-29` |
| `adaptive/budget.py` | only `adaptive/__init__.py:2` |
| `adaptive/forgetting.py` | only `adaptive/__init__.py:3`, and a docstring sentence in `adaptive/forgetting_engine.py:16` |

No test imports any of these modules or a name they define. The only reader of `StatePlane.stats()`
is `health_metrics_report` (core/stateplane.py:1952), which reads `ops_count`, `working_memory` and
`backend` only; no tool, route or test reads the `"arbiter"` key. An earlier coarse grep (backlog row
17) seemed to find `mcp_server.server` in a benchmark adapter and a script; every one of those hits is
`server_v2`, and nothing under `benchmarks/` or `scripts/` imports the shim. `docs/mcp-server.md`,
`docs/runbook.md` and `docs/security.md` name `server_v2`, not the deleted shim.

Cost today: four objects built for every `StatePlane` (one per hosted project), `bilinc.adaptive`
imports two of the modules on every import of the AGM engine, and every reader and linter of the
package reads code that never runs.

## Approaches

1. **Delete the modules and their wiring in one change (chosen).** Git history keeps the code; the
   full test suite shows nothing depended on it.
2. **Keep the files, stop constructing the arbiter objects.** Removes the per-plane objects but keeps
   unreachable code to read and lint. Rejected (delete over simplify).
3. **Move them to an `attic/` folder.** Dead code under another name. Rejected.

## Changes

- `git rm` the nine files; the then-empty `src/bilinc/retrieval/` goes with them.
- `core/stateplane.py`: drop the two imports (30-31), the four attributes (`estimator`, `s1`, `s2`,
  `arbiter`, 286-289), `route_query` (3654-3658) and the `"arbiter"` entry of `stats()` (3675).
- `core/__init__.py`: drop the names from the docstring's first line, `__all__` and the lazy map.
- `adaptive/__init__.py`: import and export only the AGM names; its docstring ("Budget Optimization
  and Learnable Forgetting") is reworded to the AGM engine.
- `adaptive/forgetting_engine.py`: the docstring sentence that names `LearnableForgetting` (line 16)
  is reworded so it no longer names a removed class; nothing else in that file changes (whether to
  wire or remove it is owner decision C10-DECIDE; it is pinned by tests/test_dormant_features.py and
  tests/test_ttl_read_points.py).
- `MANIFEST.in`: unchanged. `prune src/bilinc/retrieval` is harmless for a missing directory and is part
  of the cloud-only package boundary; it keeps guarding if `retrieval/` ever comes back.
- `CHANGELOG.md`: new `## [Unreleased]` / `### Removed`, one bullet.

Out of scope: `forgetting_engine.py` beyond its docstring; modules used only by their own tests
(`adaptive/policy.py`, `integrations/*`, `core/verification.py`, `core/consolidation.py`,
`core/blind_spots.py`, `core/belief_sync.py`), a separate, larger deletion; `mcp_server/hermes_stdio.py`
(the local stdio launcher); the forbidden-prefix lists in the two tests (they keep guarding);
`docs/architecture.md`, already inaccurate (it describes System 1/System 2 and a budget layer), a docs
follow-up named in the ready note; `pyproject.toml` (its package list names none of these).

## Test plan

Deletion only, so the proof is that nothing breaks and nothing can still reach the code:
1. New `tests/test_removed_modules.py` (internal_runtime lane): each removed module path raises
   `ModuleNotFoundError` on import; `bilinc.core` no longer exports the removed names
   (`hasattr`/`__all__`); `bilinc.adaptive.__all__` is exactly the AGM names; a `StatePlane` has no
   `arbiter`/`s1`/`s2`/`estimator` attribute and `stats()` has no `"arbiter"` key; `health_metrics_report`
   still returns its three fields. Red on 371cdfc.
2. The existing suites stay green, run before and after: tests/test_cloud_only_package.py and
   tests/test_wiki_import_boundary.py (their source-level guards run; the built-artifact checks at
   test_cloud_only_package.py:404-448 skip without `BILINC_TEST_WHEEL`/`BILINC_TEST_SDIST`, and
   nothing in the packaging changes, since `MANIFEST.in` and `pyproject.toml` stay as they are), tests/test_dormant_features.py,
   tests/test_ttl_read_points.py, tests/smoke.
3. Full gate: `bilinc-test -q -m public_source`, `-m internal_runtime` (Postgres runs), `ruff check`;
   the count of passing tests may only drop by the deleted modules' own tests (there are none).
4. A last grep in the build log: no reference to any removed module or name remains outside the guard
   lists and CHANGELOG.
