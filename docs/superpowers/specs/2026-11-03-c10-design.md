# C10: dead and half-wired features

Backlog C10 lists four stubs and says "clean up or document". Checked against origin/main 5578d27 (the claims were
re-derived, not copied):

| Item | Finding | Evidence |
|---|---|---|
| Contradictions never created | The KG only reports a contradiction for a pair of edges where one is `CONTRADICTS` (`find_contradictions`, knowledge_graph.py:421-460). Nothing in core creates such an edge: `ingest_memory_entry` (knowledge_graph.py:~463) only extracts entities and co-occurrence relations; the only way in is an explicit edge through the MCP add-relation tool (its enum offers `contradicts`, server_v2.py:456). `contradictions` in the KG stats (knowledge_graph.py:551, 602) is therefore 0 unless a caller adds such an edge. The claim-based contradiction check (`eval/contradictions.py`, used by the verified recall profile) is a different, working mechanism. | grep `EdgeType.CONTRADICTS`, `find_contradictions` over src and tests |
| `valid_at` never written | No commit path sets `MemoryEntry.valid_at`; it is only read (as-of filter stateplane.py:1848, visibility :1942, ranking :2704, graph doctor) and persisted. Values can only arrive through restore/import or direct construction. | grep `valid_at =` over src finds only storage upserts |
| Constant `verification_score` | The only writers are the state verifier outcome in `StatePlane._apply_entry_verification` (stateplane.py:342-368: 0.0 on fail at :360, 0.8 on pass at :365; verification is on in the hosted runtime, cloud/runtime.py:506) and the default 0.0; the score is read by decay, ranking inputs and `_handle_verify`. It is not a graded confidence. | stateplane.py:352-367, decay.py:136-153, server_v2.py:1572 |
| Unwired `StatePlane.verify` | NOT dead: it works (audit history, invariant checks, integrity flag; run against a fresh local plane during this review) but has no caller: the MCP `verify` tool (`_handle_verify`, server_v2.py:1565) reads the stored row itself and returns different fields. | stateplane.py:3205; grep `.verify(` finds no caller |
| `superseded_by` writer | The only core writer is `ForgettingEngine.forget_by_contradiction` (forgetting_engine.py:138), which sets `superseded_by = e.key` on `e` itself. It groups entries by key (`by_key`) and needs two entries with one key, which a key-unique store never returns, so it cannot trigger; if it ever did it would write a self-pointer. This is NOT the source of the 200 self-pointing rows Local-Audit found: the module is never imported. The likelier origin is a removed writer: until commit 665e9b5 the old AGM revise path in `core/agm.py` ran `entry.superseded_by = existing.key` on every revise, where `existing.key == entry.key` (verified in `git show 665e9b5`; the link to the 200 rows is unverified, I did not reproduce them). No current core path writes a self-pointing `superseded_by`. Nothing in src or tests imports `ForgettingEngine` or this module (`adaptive/__init__` exports `LearnableForgetting`, a different class). | forgetting_engine.py:102-142; grep over src and tests |

## Approaches
1. **Remove** the unreferenced code (`forgetting_engine.py`, `StatePlane.verify`) and the KG contradiction reporting. Smallest
   surface, but: `forgetting_engine.py` is imported by the A5r branch's test (vm/a5r, ready) so removing it creates a
   merge-order hazard for the owner; `StatePlane.verify` is a working API an outside integration may use; and deleting is a
   product decision, not a cleanup.
2. **Wire them up** (create contradiction edges at commit, write `valid_at`, compute a graded score, expose `verify`). Each is
   feature work that changes ranking or data, and the KG ones touch the blocked item A3 (entity boost hurt English recall).
   Not a worker decision.
3. **Document and pin** (chosen): say precisely in the code what is dormant, add characterization tests so a future change to
   any of them is a conscious one, and hand the product decisions to the owner as one blocked-owner row.

## Changes (no behaviour change)
- Docstrings/comments only, at: `KnowledgeGraph.find_contradictions` and `ingest_memory_entry` (explicit `CONTRADICTS` edges
  only; stats count 0 otherwise; the claim-based check is separate); `MemoryEntry.valid_at` (never set by commit; restore/import
  only); the state-verifier block in stateplane.py (fixed 0.8 / 0.0, not a graded confidence); `StatePlane.verify` (works, is not
  exposed by the MCP `verify` tool, which returns the stored row's fields); `forgetting_engine.py` module and
  `forget_by_contradiction` (not imported anywhere; cannot trigger with unique keys; would write a self-pointing
  `superseded_by`; no claim about where legacy self-pointing rows came from).
- `tests/test_dormant_features.py` (characterization, SQLite, always runs): ingesting conflicting memories creates no
  `CONTRADICTS` edge and `find_contradictions()` is empty, while an explicit edge is found; commit (local plane and hosted
  runtime) leaves `valid_at` None; with verification on the score is 0.8 after a passing check, 0.0 after a failing one, 0.0
  with verification off; `StatePlane.verify` returns the documented keys; `forget_by_contradiction` processes nothing on a real
  backend and, on a stub backend that does return two rows with one key, writes a self-pointing `superseded_by`. That last test is
  `pytest.mark.xfail(strict=True)` asserting the correct behaviour (the stub entries are built so the losing one is clearly not protected and differs from the winner in value and in `verification_score * importance`; the test first asserts `entries_forgotten == 1`, so the xfail covers only the self-pointer assertion, and nothing passes because a protected entry was skipped) (`superseded_by` is not the entry's own key), with the reason
  "forget_by_contradiction writes a self-pointer", so it flips to a failure that must be handled together with the `C10-DECIDE` outcome
  instead of pinning a bug as wanted. New: a revise through `commit` (same key committed twice, local plane and hosted runtime)
  leaves `superseded_by` None, so LOCAL-REPAIR knows rows written today are clean.
  A Postgres-marked variant (`BILINC_TEST_POSTGRES_DSN`, through the hosted runtime) checks that `valid_at` is None, that
  `superseded_by` stays None, and that the 0.8 / 0.0 scores survive a round trip (postgres.py:1400-1404 coerces these fields
  separately).
- Backlog: C10 becomes ready; one new blocked-owner row `C10-DECIDE` lists the product decisions (wire or remove each item). It does not
  mention `forgetting_engine` as the source of the 200 rows; LOCAL-REPAIR is told that no current path writes a self-pointer
  and that the removed 665e9b5 writer is the unverified likely origin.

## Test plan
The characterization tests above. The new file is not in `PUBLIC_SOURCE_FILES`, so conftest tags it `internal_runtime` (the ready note says so); the Postgres variant uses the same skip-when-no-`BILINC_TEST_POSTGRES_DSN` pattern as the other Postgres tests and runs with `BILINC_STORAGE_BACKEND=postgres` through the hosted runtime. Each one is sanity-checked by hand during the build (for example making `ingest_memory_entry` add
a `CONTRADICTS` edge, or committing with `valid_at` set must fail it); those checks are recorded in the ready note, not committed. Full `bilinc-test` set and ruff as regression.

## Release-chain impact
- None: docstrings, comments and tests only. No PyPI, SDK, hosted runtime, site, MCP registry or migration change; no
  CHANGELOG entry (nothing a user can observe). Version number is the owner's decision.
